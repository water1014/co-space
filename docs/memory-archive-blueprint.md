# 藏忆阁｜整体规划与视觉设计方案

> 版本：v1.0（方向提案）  
> 状态：待体验与讨论；本文件是后续改造的设计依据，不代表所有细节已经定案。

## 1. 核心定位

藏忆阁不是一个把日历、树和收藏堆在一起的工具页，而是一座可以进入、记录、整理、回望的私人记忆庭院。

它需要同时满足三种不同心境：

- **记录时**：轻、快、没有负担，打开就能写下今天。
- **整理时**：安静、有秩序，能找到旧内容，也能挑出值得珍藏的片段。
- **回望时**：有仪式感和情绪价值，像翻开一本属于自己的年鉴。

设计原则：日常操作优先效率，回顾体验优先氛围；数据只有一份，呈现方式可以有多种。

## 2. 信息架构：三个空间，各司其职

### A. 时日笺｜日常记录（默认入口）

这是藏忆阁真正的主空间，也是使用频率最高的页面。

主要任务：
- 快速写一段文字、添加照片或补充当天片段。
- 按日期浏览每天的记录。
- 编辑、删除、置顶或标记重要内容。
- 从某一天进入完整的记忆详情。

建议布局：
1. 顶部保留轻量标题与当前日期，不放大块欢迎卡。
2. 首屏提供一个明显但克制的「写下今天」入口。
3. 下面是日期导航与按天排列的记录流；默认最近日期优先。
4. 日期切换可用紧凑月历/日期带，不让整张大月历长期占据首屏。
5. 点某一天进入当日详情，照片与文字按时间顺序呈现。

交互重点：
- 新建记录尽量两步内完成。
- 日期筛选、搜索不应藏得太深。
- 空状态要给出明确的第一步，而不是只显示空白装饰。

### B. 珍藏页｜精选与整理

这是记忆的整理柜，不承担日常写作主流程。

主要任务：
- 查看主动收藏、置顶或标记的重要记忆。
- 通过关键词、日期、标签找到旧内容。
- 按主题整理，例如「旅行」「某个人」「某个阶段」。
- 从收藏条目回到原始日期和完整记录。

建议布局：
- 顶部是简洁搜索入口。
- 下方以轻量标签/主题筛选组织内容。
- 内容以有呼吸感的纵向条目呈现；有照片时突出照片，没有照片时不强行补图。
- 每条内容保留日期、简短摘要和来源入口。

规则建议：
- 收藏是用户主动表达“这条值得留下”，不等于树上的全部内容。
- 删除原始记忆时，应同步处理对应收藏引用，避免出现打不开的空壳。
- 标签先做少而清晰，后续再考虑自定义标签管理。

### C. 时日树｜年度回望（独立沉浸页面）

时日树是藏忆阁的总结展示空间，不是日常记录入口，也不应该挤在日历和编辑器之间。

它的意义是：把一段时间里的生活痕迹，转化为一棵可以慢慢浏览的记忆树。

建议定位：
- 默认以**年度**为单位，形成一棵完整的年度记忆树。
- 可切换年份；月份/季节作为树内浏览维度，而不是把树变成普通月历。
- 树上的挂签代表“某一天的记忆入口”，而不是每一条文字都单独挂一张签。
- 同一天多条记录先汇总为一个日摘要；点挂签后再查看当天完整内容。
- 用户主动珍藏的记忆可以用特别的签样、细小印记或光点强调，但不独占树的内容。

视觉与交互：
- 完整保留老师原版树的枝干、枝叶、挂签布局与摇摆动效，不重新手绘一棵替代树。
- 只对颜色、背景、字体与周边控件做镜花水月主题适配：月白、雾蓝、银灰、透明玻璃质感；不使用紫色。
- 树是主角，控件退后。年份切换、月份定位、回到当年等操作保持轻巧。
- 手机端优先保证树的完整观赏：允许横向拖动/滑动查看，不把宽树强行压扁；页面有明确的拖动提示和返回入口。
- 点击挂签打开记忆详情；详情中能返回树的原位置。

数据量适配：
- 记录少：树保持舒展，展示生长中的状态，不制造“空荡失败感”。
- 记录多：按年分树，避免一棵树无限堆叠；同日汇总，防止挂签爆满。
- 某月没有记录：保留时间连续性，但不伪造挂签。
- 跨年切换时明确显示年份，避免用户误以为内容丢失。

## 3. 三者之间的关系

统一数据源，不复制三份记忆：

- 时日笺负责创建和维护原始记录。
- 珍藏页保存的是原始记录的精选引用与整理信息。
- 时日树读取原始记录，按日期生成日级摘要与视觉挂签。

建议的核心数据关系：
- 一条记忆属于一个日期，可包含文字、图片、创建/更新时间。
- 一条记忆可以有收藏状态与标签。
- 同一天的多条记忆可以汇总成一个树节点/挂签入口。
- 树节点始终能定位回原始记忆，不单独产生一份无法同步的副本。

## 4. 导航建议

藏忆阁主入口默认进入「时日笺」。

在藏忆阁内部设置三个清楚的入口：
- 时日笺
- 珍藏页
- 时日树

不建议把三者做成三个同等重量的大卡片。更适合用顶部轻量分段导航、文字标签或小型空间切换器；当前所在空间要明确，其他入口不抢主任务。

时日树作为独立页面，建议路由：`/memory/tree`。从树进入日期详情时保留返回树的路径与年份/月位置。

## 5. 视觉方向

主题关键词：**东方幻想、月下庭院、蓝色雾面玻璃、克制的仪式感**。

色彩：
- 主背景：月白、冷雾白。
- 主色：低饱和雾蓝、浅青灰。
- 深色：夜色蓝，仅用于夜间主题与局部层次。
- 点缀：少量银色/暖白高光。
- 明确避免：紫色主调、奶油黄、过度粉色、荧光色。

材质与图形：
- 半透明玻璃层、柔和边缘高光、细腻阴影。
- 线条图标，统一笔画粗细与圆角。
- 装饰纹样少而精：水纹、月相、微光、细枝，不堆满页面。
- 不用大量普通白色圆角卡片；让日期、照片、留白和细线形成层次。

动效：
- 页面切换轻柔，不延误操作。
- 树保留原作自然摇摆感。
- 重要操作有短暂反馈，避免持续漂浮、闪烁等干扰阅读的效果。

## 6. 手机优先的体验约束

- 主要操作区域适合单手触达，触控目标留足空间。
- 重要入口和返回路径始终清楚。
- 纵向阅读作为记录流主模式；只有时日树这种具有空间构图的内容才使用横向浏览。
- 不把桌面端复杂布局缩小后直接塞进手机。
- 长列表需要日期定位、搜索或筛选，不能只靠无限滚动。
- 图片按屏幕宽度自适应，避免裁掉记忆主体。

## 7. 实施顺序

### 第一阶段：梳理与拆分
1. 保留现有数据结构与已有记录，先盘点现有记录、收藏、日历功能。
2. 将藏忆阁主入口明确为时日笺。
3. 将时日树从主记录页面拆为独立路由。
4. 珍藏页独立承担收藏与搜索，不复制原始数据。

### 第二阶段：体验打磨
1. 完成时日笺的快速记录与日期浏览。
2. 完成珍藏页的搜索、筛选、回到原文。
3. 为时日树加入年度切换、日级摘要、挂签回跳。
4. 统一日间/夜间主题与移动端细节。

### 第三阶段：扩展能力（暂不抢先实现）
- 年度回顾摘要与阶段主题。
- 自定义标签与主题整理。
- 记忆照片墙、纪念日关联。
- 与共同记录/相册等其他空间的关联。

## 8. 验收标准

改造完成不能只看代码是否构建成功，还要逐项验证：

- 打开藏忆阁，第一眼能明确知道如何记录今天。
- 新建、编辑、删除一条记忆后，时日笺、珍藏页和时日树的数据关系正确。
- 收藏内容能回到原始日期和原文。
- 时日树是独立页面，返回路径清晰。
- 同一天多条记录不会挤爆树上的挂签。
- 切换年份后不会混入其他年份的记录。
- 手机端能顺畅浏览树、打开挂签、返回原位置。
- 日间与夜间配色都保持清晰可读。

## 9. 暂时不做的决定

以下细节需要结合真实页面和现有数据再定，不在本轮仓促拍板：
- 年度树是否提供季节视图。
- 日摘要由系统自动生成还是由用户手动选择代表内容。
- 挂签是否显示摘要、关键词或仅显示日期。
- 标签是否支持层级与自定义颜色。
- 是否把相册中的照片自动关联到当天记忆。

## 10. 设计依据

本方案优先考虑手机上的清晰导航、较少层级、明确返回路径，以及按时间组织内容并辅以搜索/分类的方式。移动端信息架构资料强调聚焦高频任务、控制导航复杂度并保持路径明确；记忆类产品也常将日常记录与后续回顾分开组织。
